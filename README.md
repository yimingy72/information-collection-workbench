# 信息收集工作台

> 最后更新：2026-09-04

信息收集工作台是一个面向**已获授权的信息核验场景**的企业关联主体与 ICP 备案查询工作台。平台先通过企业数据源识别根企业及符合条件的对外投资企业，再按企业名称查询工信部备案信息，并把查询过程、结果、错误和耗时保存为可追踪的历史记录。

当前一级页面：

- **ICP备案查询**：输入企业名称、数据源、查询深度和最低持股比例，查看“对外投资”和“ICP备案”两类结果。
- **历史查询**：按企业和状态筛选历史任务；点击记录后在当前页面切换到单独的详情视图，可返回列表。
- **子域名查询**：支持单域名、批量域名及从历史 ICP 备案结果选取域名，查询结果实时输出。
- **基础配置**：分别配置数据源登录状态和 SeaMoon 云函数代理。
- **代理设置**：维护手动 HTTP(S) 代理；检测成功后加入 ICP / 爱企查代理轮换。

## 当前能力

- 数据源：天眼查、爱企查、快查、风鸟。
  - 天眼查使用匿名接口。
  - 爱企查、快查、风鸟需要在“基础配置 → 数据源配置”扫码登录。云函数启用时，爱企查查询使用 SeaMoon 代理。
- 按查询深度（1～5层）和最低持股比例过滤对外投资关系。
- 根企业优先进入 ICP 查询；投资关系遍历过程中发现符合条件的关联企业后，会立即投递 ICP 查询，不必等待全部投资关系结束。
- 投资关系按最多 12 家企业并发抓取，失败企业只定向重试自己，不回退整棵树。
- ICP 多页完整性校验、跨页去重、有限次数补全和明确的部分成功状态。
- SeaMoon 云函数一键部署：阿里云函数计算 FC、腾讯云函数 SCF。
- SeaMoon 支持按地域部署多个云函数节点，网关会对已验证节点轮询并在连接失败时尝试其他节点。
- 查询结果导出为一个 Excel 兼容 `.xls` 文件，包含“对外投资”和“ICP备案”两张工作表。
- 子域名任务支持刷新恢复：历史任务和进行中任务从服务端加载，DNS 首次结果与后续 HTTP 丰富结果通过 SSE 增量推送；多主域名最多同时处理 3 个根域名。
- ICP 云函数节点池按任务规模自动扩容，任务完成后只回收平台自动创建的闲置节点，不删除主节点或手动节点。
- 历史列表使用服务端分页；查询结果表使用本地分页，默认每页20条，可切换10/20/50条。
- PostgreSQL 持久化任务、实体、关系、结果、运行配置和错误信息。

## 子域名查询

子域名模块参考 OneForAll 的处理流程重新实现，没有直接复制其 GPL-3.0 源代码。当前流程包括：

- 并行调用 `crt.sh`、`CertSpotter`、`HackerTarget`、`urlscan.io`、`RapidDNS`、阿里公共 DNS JSON、SRV 记录、站点元数据和 Common Crawl 九类数据源；单个来源失败会按错误类型重试或进入限流冷却。
- 被动来源结果默认缓存 6 小时，重复查询同一主域名时优先复用缓存，减少外部限流和等待；429 不通过代理轮换硬绕过，而是遵守来源限速并暂停该来源。
- 使用内置常见前缀字典补充 DNS 枚举；可选“智能变体”会对已观察到的名称执行有限数字/词语变体，字典解析与较慢的被动来源并行，已验证结果会提前进入实时列表。
- 对三个随机不存在域名做解析，合并轮询地址后识别泛解析；仅由字典命中的泛解析结果会过滤，被动来源命中的结果会保留并标记。
- 使用离线 Public Suffix List 提取可注册主域名，避免把 `com.cn` 等公共后缀误当成主域名。
- 通过系统 DNS 并发验证 A/AAAA 地址，仅保存可以解析的子域名。
- 可选探测 HTTPS/HTTP 80/443，记录状态码、最终地址和页面标题，并从响应正文提取同主域名引用；每次重定向都会重新校验目标，私有、回环及链路本地地址不会发起 HTTP 请求。
- PostgreSQL 保存任务、结果和被动来源缓存，Worker 后台执行；前端通过 SSE 实时接收新增结果和节流后的进度。
- 单次最多 200 个主域名、每个主域名最多 10,000 个候选。
- 被动数据源局部失败会记录为警告，不影响 DNS 字典和其他数据源继续完成。

入口支持两种方式：

1. “输入域名”：输入一个或多个域名，支持换行、空格、逗号或分号分隔。
2. “选择 ICP 结果”：选择一条或多条 ICP 查询记录，再勾选其中需要枚举的备案主域名。

结果可实时分页查看，并导出 UTF-8 CSV。页面使用延迟筛选、增量结果合并和来源计数，避免大结果集下每条 SSE 消息都触发完整数组扫描。

### 与 OneForAll 的参考边界

本模块参考了 OneForAll 的非破坏性核心工作流：多来源收集、DNS 字典、DNS 解析、泛解析识别、HTTP 丰富、页面引用发现和 AltDNS 风格变体；没有复制其 GPL-3.0 源码。OneForAll 中需要账号/API Key 的搜索引擎、资产情报源、CDN 指纹、接管检查、端口扫描和 AXFR 等模块没有默认接入：这些功能存在额外授权、限流或安全边界，不能把“发现结果更多”误认为“无条件安全”。当前平台会尽量合并公开数据源与可验证 DNS 结果，但不能保证覆盖未公开、已下线或仅内网可见的子域名。

## 查询流程

```text
用户提交企业名称
    ↓
创建后台任务并立即返回，页面通过 SSE 接收实时结果
    ↓
所选企业数据源搜索根企业
    ↓
按深度和持股比例采集对外投资关系
    ↓
根企业及新增投资企业即时投递 ICP 查询（代理模式最多5家并发）
    ↓
优先复用未过期且完整性校验通过的企业级缓存；未命中则实时分页查询
    ↓
保存结果并标记成功 / 部分成功 / 失败
```

代理路由按一次查询开始时的配置快照决定，不在查询页面单独选择，也不会在同一轮查询中混用手动代理和云函数：

- 有至少一个“已启用且检测成功”的手动代理时，ICP、爱企查和天眼查只使用手动代理池；云函数不会参与本轮调用。
- 没有可用手动代理、且云函数已验证启用时，上述三个业务使用 SeaMoon 云函数网关。
- 两者都不可用时，当前保留直连兜底；如仍要求 ICP 严格禁止直连，需要把该兜底改为“暂无可用代理”失败。
- 快查、风鸟及扫码登录链路保持直连。

## ICP 查询规则

当前规则以 `/backend/app/miit.py` 为准：

- 工信部单页大小：**26条**。
- ICP 按企业全称缓存完整快照：非零结果默认 **24小时**，明确成功的零结果默认 **6小时**。只有算法版本一致、未过期、`saved_total = reported_total` 且缓存内容重新去重后数量仍完全一致时才命中。
- 超时、WAF、业务异常、分页不完整和部分结果不会写入缓存；缓存读取或校验异常会自动回退实时查询，不会用旧结果冒充本轮成功。查询结果头会显示缓存命中企业数和实时查询企业数。
- 单页请求：`httpx` 超时与 `asyncio.timeout` 双重硬超时，最多 **36秒**。
- 单个企业每次 ICP 查询预算最多 **80秒**；失败企业默认执行 **2次企业级尝试**，轮次间按0.5秒退避。
- ICP 与投资关系遍历并行：根企业或新增投资子企业持久化后立即进入 ICP 队列；根企业即时查询，后续企业尽量积累到320家后再批量填充云池，避免小批次造成大量串行波次。
- 查询页面不再等待同步接口返回：提交后立即进入任务详情，通过 SSE 增量接收投资关系、ICP 记录和任务进度；刷新页面会先载入当前快照，再从游标位置继续接收，最终完成时重新校准完整结果。
- ICP 企业调度使用滚动并发槽位：任一企业完成后立即补入下一家，不再等固定切片中最慢的企业超时结束后才启动下一组。
- 运行中的任务可在结果卡右上角直接停止；停止后保留已写入的投资关系、ICP 结果和完整缓存，最长约5秒终止仍在执行的 ICP 协程。
- 云函数模式按就绪节点数扩展，当前每节点5个逻辑槽位，最多40个逻辑并发；手动代理模式按已就绪节点数并发，每个手动代理同一时间只承载1家企业。直连模式仍串行节流，避免固定出口触发 WAF。
- “每5次”是**实际 ICP 页面请求**的轮换阈值，不是每批5家企业的调用次数；一个企业有多页时，页面请求会累计消耗阈值。
- 云函数路由达到5次页面请求后进入下一代 YMICP/SeaMoon 会话；创宇盾拦截时对当前页最多重建2次隧道后重试。
- 正常 `code=200 + total=0` 或已返回有效备案记录时立即结束；正数 `total` 但空列表仅执行1次快速恢复，再交给企业级重试，避免单企业重复9次慢请求。
- 云函数批次不套用直连出口的全局冷却；不同企业使用独立分页会话和 SeaMoon 隧道。单个手动代理不会套用云函数代际轮换，会保持同一分页会话。
- YMICP 只对无分页会话的兼容调用保留全局验证码锁；平台查询使用独立分页会话，因此不同手动代理节点和 SeaMoon 隧道可并行完成验证码流程。
- 直连模式：请求间隔约0.4秒，每累计5次请求等待12秒。
- 同一轮分页使用会话标识保持 YMICP 上游会话亲和。
- 工信部偶发返回重叠分页时，平台按“域名 + 服务备案号”合并，最多执行1次初始分页和2次恢复分页；无域名记录改用主备案号/主ID识别，不再误报为0条。
- 每轮结束后只把失败企业重新加入下一轮，已成功企业不会重复查询；每次企业级尝试使用新的分页会话。
- 只有合并后的唯一记录数达到上游报告的 `total` 时才写入该企业的 ICP 结果；否则标记“结果不完整”。
- 查询失败信息包含企业名、企业尝试次数、累计请求页面次数、最终错误和累计耗时。
- ICP 阶段持续刷新任务心跳，避免长查询被误判为 worker 租约过期。

## 爱企查代理规则

- 爱企查与 ICP 共用当前选中的代理路由；手动代理优先，只有没有可用手动代理时才使用已启用的 SeaMoon 云函数。
- 每个爱企查客户端最多复用同一条 HTTP CONNECT / WebSocket 隧道发送 **15次实际 HTTP 请求**，第16次请求前主动关闭客户端并建立新隧道。
- 网络连接重试会立即重建隧道；遇到安全验证、HTTP 401、403 或429时，下一次请求也会先轮换隧道。
- 轮换隧道会创建新的云函数请求，但云平台仍可能复用同一实例，因此不能承诺公网出口IP一定变化。
- 扫码登录链路保持直连，不计入15次请求。

## Docker 启动

仓库目录名包含中文时，Docker Compose 可能无法自动生成项目名，建议始终显式指定：

```bash
cp .env.example .env
docker compose -p asset-workbench up -d --build
```

生产构建后的前端由 API 容器提供：

- 工作台：<http://127.0.0.1:8000>
- 健康检查：<http://127.0.0.1:8000/api/health>

API 默认只绑定宿主机回环地址。当前没有平台登录和租户隔离，不要直接把8000端口暴露到公网。

### YMICP 服务

YMICP 当前作为外部容器运行，不在本仓库的 `docker-compose.yml` 中自动创建。示例：

```bash
docker run -d \
  --name ymicp \
  --restart unless-stopped \
  -p 127.0.0.1:16181:16181 \
  yiminger/ymicp

docker network connect asset-workbench_default ymicp
./scripts/apply_ymicp_patch.sh
```

如容器已连接 `asset-workbench_default` 网络，推荐在 `.env` 中使用：

```dotenv
MIIT_API_URL=http://ymicp:16181
```

本地直接运行后端时可使用 `http://127.0.0.1:16181`。补丁脚本会更新 YMICP 的分页参数处理、SeaMoon 白名单代理、分页会话亲和和验证码适配，然后重启名为 `ymicp` 的容器。

## 本地开发

后端要求 Python 3.12+：

```bash
cd backend
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

另开终端启动 worker：

```bash
cd backend
. .venv/bin/activate
python -m app.worker
```

前端：

```bash
cd frontend
npm ci
npm run dev
```

Vite 开发地址默认是 <http://127.0.0.1:5173>，并把 `/api` 转发到 <http://127.0.0.1:8000>。

## SeaMoon 云函数配置

“基础配置 → 云函数配置”只支持平台托管的一键部署：

1. 选择阿里云 FC 或腾讯云 SCF。
2. 填写地域、函数名称和云账户 AK/SK。
3. 点击“一键部署”。平台会创建或复用函数、创建或复用触发器、验证代理并自动启用。

操作含义：

- **保存**：只保存云平台配置，不改变当前查询路由。
- **一键部署**：部署或更新函数，测试成功后启用。
- **测试**：只验证链路，不切换路由。
- **停止**：关闭平台到 SeaMoon 的 ICP 和爱企查查询路由，不删除云端函数。
- **删除**：删除由平台托管的云函数，并关闭代理。

托管规格：**0.1 vCPU、128 MB内存、512 MB磁盘、单实例并发6、最小实例0**。最小实例为0表示没有请求时不保留预置实例，但云平台仍可能按其计费规则产生镜像、日志、流量或其他资源费用。

### 云函数节点池

- 在“基础配置 → 云函数配置”中选择新的地域和函数名称，再点击“一键部署”，不会覆盖其他地域节点，而是把新节点加入池。
- 当前已部署节点会显示在“节点池”表格中；删除节点只删除选中的云函数。
- SeaMoon 网关按新 HTTP 代理连接轮询节点，连接失败时会尝试其他已配置节点。
- ICP 每个节点按 **5 个逻辑并发槽位**计入容量；爱企查每个节点按 **15 次实际 HTTP 请求**计数。
- ICP 会根据本轮已发现的企业数量自动扩容云函数节点：默认以 5 分钟目标、每节点 160 家企业的保守容量估算，最多 8 个函数节点。优先使用不同大陆地域；地域用尽后会在健康地域追加副本函数（`asset-workbench-seamoon-r2`）。单个函数内部仍由阿里云按并发自动拉起多个容器，不保证出口 IP 不同。新增节点先探活，批次开始前会对就绪节点做 `/_health` 预热。
- 5 分钟是健康云节点和上游正常响应下的目标，不是对第三方 WAF、云平台配额、网络故障的绝对保证；超过目标时任务会保留已完成结果并标记部分成功。
- 多地域只能增加出口候选，不能保证每个节点公网 IP 一定不同。需要固定且互不相同的出口时，应在云平台为节点配置独立 NAT/EIP。
- 香港节点不纳入中国大陆 ICP 代理池。

### 手动代理

“代理设置”页面支持手动添加 `http://用户名:密码@主机:端口`，也支持省略 `http://`。代理检测使用百度 robots 地址；只有检测成功的节点才会加入 ICP / 爱企查轮换，检测失败的节点会自动停用。密码只保存在后端，列表只显示掩码。

SeaMoon 每个上游 HTTP 代理连接建立一个 WebSocket 隧道。使用同一个函数地址不保证每次请求获得固定出口 IP；多节点网关只负责轮换候选出口，不承诺运营商层面的 IP 唯一性。

## API 示例

同步执行一次查询并返回完整视图：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/queries \
  -H 'content-type: application/json' \
  -d '{
    "keyword":"小米科技有限责任公司",
    "providers":["tianyancha"],
    "depth":3,
    "holding_percent":100,
    "fields":["invest"],
    "include_branches":false
  }'
```

创建异步任务：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/collection-runs \
  -H 'content-type: application/json' \
  -d '{
    "keyword":"小米科技有限责任公司",
    "providers":["tianyancha"],
    "depth":3,
    "holding_percent":100,
    "fields":["invest"],
    "include_branches":false
  }'
```

读取任务与结果：

```bash
curl 'http://127.0.0.1:8000/api/v1/collection-runs?limit=20&offset=0'
curl http://127.0.0.1:8000/api/v1/queries/{run_id}
curl 'http://127.0.0.1:8000/api/v1/collection-runs/{run_id}/results?limit=20&offset=0&relationship_limit=20&relationship_offset=0'
```

## 数据、安全与范围

- PostgreSQL 是任务队列和结果事实源；原始数据源响应保存在 `raw_payload`。
- worker 使用 `FOR UPDATE SKIP LOCKED` 和 `lease_id` 防止重复领取与旧租约覆盖。
- 云账户 Secret 保存在后端数据库中；API 只返回“是否已配置”，不会把 Secret 返回前端。
- SeaMoon 或手动代理仅用于 ICP、爱企查和天眼查业务查询；快查、风鸟以及数据源登录流程保持直连。
- 天眼查匿名接口可能返回“请登录以使用完整功能”；这属于上游权限限制，不能通过代理轮换解决。
- 已删除的免费代理池模块不再读取、验证、轮换或展示；旧表和迁移仅作为历史结构保留。
- 当前不支持分支机构、平台账号体系、租户隔离、固定云函数出口IP和永久 HTML/PDF 证据归档。
- 仅允许在已授权范围内进行非破坏性查询，禁止数据破坏、持久化攻击或越权扩散。
