# 查询性能与完整性审计

> 2026-09-09。范围：当前工作区的投资遍历、ICP、子域名发现、缓存与任务生命周期。

## 结果

本轮减少了分页串行等待和 DNS/HTTP 批次屏障，统一了来源请求预算，并修复会导致静默缺失或任务无法结束的处理。没有通过删减结果、降低验证步骤、提高第三方请求额度或绕过 429 获得提速。

工作区原有的 PostgreSQL 事件通知、SSE 游标恢复、前端分包和分页修改均保留；它们不是本轮新增内容。没有修改真实凭证、删除历史结果或执行第三方真实查询。

## 并发预算

| 阶段 | 当前上限与作用域 | 审计结论 |
| --- | --- | --- |
| 企业任务 | 2 个 worker；现有 provider 锁覆盖投资阶段 | 保留任务级预算，避免以增加任务数量放大请求 |
| 投资主体 | 每个来源、每层最多 20 家 | 同层滚动处理；层间等待保证共享企业按最浅深度访问 |
| 投资分页 | 单企业最多 4 页；按窗口创建协程 | 四个来源统一实现；不一次创建全部分页任务 |
| 企业 HTTP | 每来源每进程 20；企业、分页、实例共用 | 消除 20 家 × 4 页导致的 80 请求叠加；不同来源仍独立 |
| ICP | 云函数每就绪节点 5 槽、最多 40；手动代理 `min(40, max(8, 入口数))`；直连最多 5 | 保留原预算、会话和直连节流；独立任务仍受进程内 ICP 锁串行约束 |
| 子域名根域名 | 每进程 5 | 多任务共用，不再按子域名 worker 数倍增 |
| 候选 DNS | 每进程 64；专用执行器 64 线程 | 系统解析的排队时间不计入响应超时；临时失败重试一次 |
| 站点 HTTP | 每进程 20；每根域名 HTTP 待处理队列最多 40 | 满队列等待，禁止丢候选；DNS 与 HTTP 独立消费 |
| 被动来源 | 每个来源串行、共享冷却；不同来源并行 | 保留来源内部的请求额度；429 不通过代理重试绕过 |
| PostgreSQL | 每进程连接池 2～20；DNS/HTTP 结果每 80 条或定时落库 | 串行化同一根域名的批量写入，完成屏障等待在途写入提交 |

企业 HTTP 预算可通过 `PROVIDER_REQUEST_CONCURRENCY`（1～64，默认 20）调整；分页预算由 `PROVIDER_PAGE_CONCURRENCY`（1～8，默认 4）控制。两个设置已传入 compose 的 API 和 worker。

所有内存信号量、来源冷却和 ICP 锁都是进程级机制。API 同步接口与 worker、多个 worker 副本之间并不共享这些预算。当前没有增加副本或同步接口并发；横向扩容仍需先加入跨进程调度和代理路由隔离。

## 修复的完整性问题

1. **短页提前结束、重叠页凑总数。** 四个投资来源按主体 ID（股东按姓名）去重，明确区分缺少总数与 `total=0`；有总数时按唯一记录数核对，失败页定向重试，重叠缺口最多恢复一遍。缺页或总数变化不会切片后标成功。默认 50 页上限已移除。
2. **部分投资页全部丢失。** 分页异常携带已获取记录，collector 保存有效关系并继续遍历这些子公司，同时将缺口计入任务错误。
3. **共享企业先被深路径“占用”。** 投资遍历改为逐层并发，共享企业只在最浅可达层展开，防止深路径先到达深度上限后漏查其后代，也避免在途企业重复抓取。
4. **ICP 名单尾部丢失。** 运行中保持增量游标；所有企业生产者完成后，核对一次数据库中的完整企业集合，补齐最后提交以及提交顺序与序列号顺序不一致的记录。
5. **ICP 缺少总数也成功。** 无 `total`、总数为负、数量不一致或超时时明确报告错误；已经获取的有效记录仍保存。完整缓存仍要求唯一记录数严格等于 `total`，不完整结果不写缓存。ICP 返回 HTTP 429 时进入进程共享冷却，不继续企业重试或轮换会话。ICP 的 50 页限制移除，原有 80 秒单企业预算仍有效。
6. **子域名数量截断。** 已获取候选不再截断到 10,000 个；固定数量 worker 消费去重队列。10,021 个候选的回归测试验证每个候选都被解析并完整保存。
7. **来源额度被当作完整结果。** CertSpotter、urlscan、Common Crawl、AlienVault、Wayback、FOFA、Hunter 出现下一页、已知总数缺口或达到返回额度时，保留现有候选并记录 `[结果不完整]`。任务即使有解析结果也为 `partial`；来源请求额度和付费请求数上限未放宽。
8. **旧缓存掩盖缺口。** 子域名来源缓存改用 `v2:<来源名>` 键；旧缓存不当作新算法的完整结果复用，保留到自然过期。带完整性缺口的来源不写完整缓存。
9. **DNS 暂时失败被当作不存在。** NXDOMAIN/无记录与暂时失败分开处理；后者重试后仍失败会留下缺口。SRV 响应现在按根域名过滤目标主机，修复按 `_service._tcp` 查询名过滤导致漏掉同根域目标的问题。
10. **并发切换客户端中断请求。** 爱企查和天眼查切换代理时，旧 HTTP 客户端等待其在途请求完成才关闭；不用保留到整个大任务结束。
11. **worker 异常、取消与落库竞争。** 队列异常立即上报并取消兄弟任务，避免 `queue.join()` 永久等待。子域名每 5 秒独立续租；存储错误不再降格成普通来源提示。任务完成前等待正在执行的批量写入，防止探测结束先取消定时落库协程。

## 使用边界

- 有限来源额度、第三方权限、上游遗漏、缓存时效与网络故障仍会限制外部可发现数据。平台保证不再用上述截断或数量不一致冒充完整，不承诺发现未公开或仅内网可见的域名。
- 投资按层遍历会让下一层等待本层最慢企业，这是最浅深度完整性的必要约束；同层企业及已知分页继续并发，ICP 与投资发现保持重叠。
- 缺少权威总数的投资来源仍只能按接口末页约定判断结束；重复满页会报错，后续才出现总数也会要求重新核验。
- 子域名只持久化 DNS 有效结果，HTTP 访问和重定向的公网地址检查保持不变。系统 `getaddrinfo` 已开始的线程调用不能强制中断，取消后不会继续采集落库。
- 第一次升级后的子域名来源缓存命中率可能下降，因为旧算法缓存不再复用。现有来源额度、冷却、ICP 超时与路由边界保持有效。

部署按 `Dockerfile.local` 重建本地 `api` / `worker`；不重启 PostgreSQL、YMICP 或其他项目容器，不更改云上节点。
